# 动作描述过滤功能说明

## 功能概述

本功能允许用户在视频描述生成过程中，通过大模型API对生成的描述进行过滤，只保留动作相关的内容，去除环境、人物衣着等无关信息。

## 使用步骤

### 1. 配置API信息

在使用动作描述过滤功能之前，需要先配置大模型API信息：

1. 打开软件，进入「配置」选项卡
2. 找到「算法配置」部分的「API配置（动作描述过滤）」组
3. 填写以下信息：
   - **API端点**: 大模型API的完整URL（如：`https://api.openai.com/v1/chat/completions`）
   - **API密钥**: 您的API密钥
   - **API模型**: 使用的模型名称（如：`gpt-3.5-turbo`）

### 2. 启用动作描述过滤

1. 进入「视频描述」选项卡
2. 在左侧「功能选项」区域找到「只保留动作描述」选项
3. 勾选该选项

### 3. 处理视频

1. 上传要处理的视频文件
2. 设置描述要求
3. 点击「开始描述」按钮
4. 系统会自动生成视频描述，然后调用API进行动作描述过滤

## 功能特点

- **智能过滤**: 使用大模型API智能识别和保留动作相关内容
- **原文保持**: 过滤过程中不对原文进行润色，保持原始表达
- **错误处理**: 当API配置不完整或调用失败时，会自动使用原始描述
- **实时日志**: 过滤过程中会显示详细的日志信息

他正在做一系列的舞蹈动作：首先他举起双臂过头顶，然后向左转身，

## 注意事项

1. **API密钥安全**: 请妥善保管您的API密钥，不要泄露给他人
2. **网络连接**: 使用此功能需要稳定的网络连接
3. **API费用**: 调用大模型API可能产生费用，请注意控制使用量
4. **配置检查**: 如果过滤功能不生效，请检查API配置是否正确

## 故障排除

### 问题：过滤功能不生效
**解决方案**：
1. 检查是否勾选了「只保留动作描述」选项
2. 确认API配置信息是否完整且正确
3. 检查网络连接是否正常
4. 查看日志信息了解具体错误原因

### 问题：API调用失败
**解决方案**：
1. 验证API密钥是否有效
2. 确认API端点URL是否正确
3. 检查API服务是否正常运行
4. 确认账户余额是否充足

### 问题：过滤效果不理想
**解决方案**：
1. 尝试使用不同的API模型
2. 调整API请求参数（如temperature值）
3. 检查原始描述质量是否良好

## 技术实现

本功能通过以下方式实现：

1. **配置管理**: 通过`cache_config.txt`文件存储API配置信息
2. **API调用**: 使用HTTP POST请求调用大模型API
3. **错误处理**: 完善的异常处理机制确保功能稳定性
4. **日志记录**: 详细的日志记录便于问题排查

## 配置文件格式

`cache_config.txt`文件中的API相关配置：
```
api_endpoint=https://api.openai.com/v1/chat/completions
api_key=your-api-key-here
api_model=gpt-3.5-turbo
```

## 重要说明：内容替换机制

**过滤后的描述会完全替换原始描述**

启用动作描述过滤功能后，经过API过滤的内容将完全替换原始的视频描述，用户在任何地方看到的都将是过滤后的结果：

### 替换范围
- **结果保存**: 保存到结果文件中的是过滤后的描述
- **界面显示**: 视频列表和结果查看器显示过滤后的内容
- **导出功能**: 所有导出格式（JSON、TXT、CSV、MD）都使用过滤后的描述
- **日志记录**: 处理完成日志中记录的是最终的过滤结果

### 处理流程
1. **生成原始描述**: 系统首先生成完整的视频描述
2. **API过滤处理**: 如果启用过滤功能，将原始描述发送到大模型API
3. **内容替换**: 过滤后的描述直接替换原始描述
4. **结果输出**: 替换后的描述作为最终结果保存和显示

### 注意事项
- 原始的完整描述不会被保留
- 一旦启用过滤功能，用户无法查看未过滤的原始描述
- 如需保留原始描述，建议先不启用过滤功能进行一次处理，再启用过滤功能进行第二次处理

这种设计确保了用户获得的是经过精确过滤的动作描述，避免了信息冗余，但同时也意味着原始信息的不可恢复性。
